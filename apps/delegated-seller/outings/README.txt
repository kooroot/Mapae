마패 아케이드 서버 외출 — 단일 Mac mini 운영

기본 상태는 꺼짐이다. 웹만 배포해도 실행 가능하다고 표시하지 않는다. 이미 사용하는
seller 프로세스 안에서 2초마다 큐 한 건을 처리하므로 새 서버나 cron이 필요 없다.
실행은 규칙 기반 시뮬레이션이며 LLM, 실시간 관전, NFT, ERC-8004와 무관하다.

활성화 순서
1. 기존 seller.sqlite를 현재 운영 백업 절차로 백업한다. 같은 STORE_PATH를 유지한다.
   새 arcade_outings/arcade_outing_lease 테이블은 seller 기동 시 생성된다.
   기존 상품·주문·정산 테이블과 SQLite user_version은 변경하지 않는다.
2. 최신 코드를 pull하고 저장소 루트에서 bun install --frozen-lockfile, bun run check를
   실행한다. 기존 작업은 중단/복구 후 배포한다. 두 seller 프로세스를 띄우지 않는다.
3. seller의 비공개 환경 파일에 ARCADE_OUTINGS_ENABLED=true와
   ARCADE_AGENT_PRIVATE_KEY를 설정한다. 새 전용 비수탁 세션 서명 키를 사용한다.
   이 키에는 GIWA ETH를 입금하지 않는다. 배포자·facilitator·bootstrap·revocation
   키를 복사하지 않는다. 키 생성과 보관은 운영자의 비밀 관리 절차에서 한다.
   소스 코드, 화면 출력, 셸 인자, 채팅, VITE_*에 키를 넣지 않는다.
4. ARCADE_RECEIPT_TOKEN은 기존 웹 Workers와 seller가 공유하는 서버 전용 토큰이다.
   새 비밀이나 공개 토큰을 만들지 않는다. 두 Workers의 배포도 함께 완료한다.
5. 실제 서비스 이름을 확인하여 기존 io.mapae.delegated-seller LaunchDaemon을 재시작한다.
   다른 이름을 추측해 새 LaunchAgent를 등록하지 않는다.
6. 웹에서 지갑 로그인 후 서버 외출의 활성 상태와 에이전트 공개 주소를 확인한다.
   최초 사용자 테스트는 1 mUSDC 입장권 한 장 한도로 한다. 이 문서나 테스트 명령 자체는
   온체인 결제를 실행하지 않는다. 실제 외출은 사용자가 서명·시작해야 실행된다.

서명·결제 경계
- 사용자 서명은 GIWA Sepolia의 배포된 스마트 계정 소유자에게서 복원한다.
  에이전트 주소, mUSDC, 고정 상점 수취인, 입장 횟수×1 mUSDC 기간/누적 한도,
  60초 기간, 2시간 만료의 caveat 전체를 정확히 비교한다. 임의 상품/수취인/체인 거부.
- 브라우저는 개인 키를 보내지 않는다. 서버에는 해당 외출의 제한된 root 권한만 전달된다.
- 서명한 Payment-Signature 원문을 SQLite FULL/WAL로 저장한 뒤 seller에 제출한다.
  응답 소실/재시작 시 같은 헤더만 복구한다. 새 leaf로 재결제하지 않는다.
- seller 주문/정산 저널이 금융 사실의 원본이다. 서버 결과 생성 전 영수증의 게임·계정·
  토큰·수취인·정확한 금액 및 GIWA의 성공 영수증/Transfer 로그를 별도로 확인한다.
- 확인된 결제는 시뮬레이션 전에 저장한다. 시뮬레이션 실패 후 복구는 다시 결제하지 않는다.
- 만료되면 새 결제를 중지하되 이미 제출한 결제의 영수증 확인은 가능하다.

중지·복구·재시작
- 중지는 다음 입장권 생성을 막는다. 이미 제출한 한 건은 동일 결제의 영수증을 확인한 뒤
  해당 게임 결과까지 완성하고 멈춘다. 아직 미확정이면 중지 요청도 확인 대기로 남는다.
- 프로세스가 실행 도중 죽으면 해당 건은 일시 정지된다. 소유자 지갑으로 불러오고
  '다시 확인'하면 저장된 동일 헤더를 재제출한다. DB 행이나 헤더를 삭제하지 않는다.
- 확인된 거래는 결과 기록으로 복구할 수 있다. 실패 메시지는 공개된 고정 코드만 반환한다.
- 서명 키를 바꾸기 전에 기존 외출을 정지·정산한다. 새 키는 이전 키의 미확정 권한으로
  결제하지 않는다(key_changed). 잔여 권한은 소유자가 철회하거나 만료를 기다린다.
- ARCADE_OUTINGS_ENABLED=false 후 재시작하면 작업 실행이 멈춘다. DB 파일은 유지한다.
  즉시 장애 중지 시 이미 전달된 정산 한 건까지 없어진다고 주장하지 않는다.

용량과 보호
- 사용자별 활성/확인 대기 외출 최대 12개, 전체 활성/대기 최대 256개.
- 입장권 한 외출 최대 36개. 모든 결제는 직렬 처리한다. DB lease는 중복 프로세스를 막지만
  다중 서버 운영을 위한 분산 큐가 아니다. 단일 seller 운영 규칙을 유지한다.
- 결과는 최대 16 KiB, 응답은 활성 건 우선 최근 24개까지. 완료된 이전 DB 결과는 유지한다.
  응답의 기록은 웹의 지갑별 클라우드 프로필에 합쳐진다.
- 완료/정지한 작업의 root 권한은 지우며, 중복 방지용 권한 해시와 결과는 남긴다.
- SQLite 백업에는 아직 살아 있는 제한된 서명 권한이 포함된다. DB/백업/환경 파일은
  운영 사용자만 읽을 수 있게 관리한다. 지갑 owner를 받는 API는 서버 토큰 없이 거부한다.

로컬 검증(결제 없음)
  저장소 루트: bun test apps/delegated-seller/outings
  seller 디렉터리: bunx tsc --noEmit
실제 SQLite 재열기, 응답 소실, 재시작, 동시 실행, 입장 한도, 중지, 키 교체, 서명 위조,
수취인/체인/금액 오류와 Transfer 검증을 가짜 결제 전송으로 검사한다.

운영 확인과 통계
- 같은 지갑의 같은 캐릭터에는 활성 외출 하나만 허용한다. 다른 기기에서 별도 서명을
  동시에 보내더라도 DB 트랜잭션에서 중복 시작을 거절한다.
- 서명한 결제 헤더/확인된 거래가 없는 만료 작업은 64건씩 정리하여 정지 상태로 전환한다.
  미확정 헤더 또는 이미 확인된 거래는 만료를 이유로 삭제하거나 슬롯에서 숨기지 않는다.
- UI의 expiresAt 값은 Unix 밀리초다. 지갑 결과 수첩은 최신 40건을 유지한다.
- 동기화 응답은 16 MiB를 넘을 수 없다. 예를 들어 흥정상회 864판의 결과는 약 3.3 MiB다.
  실제 엔진 결과 크기에 따라 달라지며 각 판 결과는 16 KiB로 제한한다.
- 별도 분석 서비스를 추가하지 않는다. 운영자는 기존 Wrangler D1 운영 절차에서
  apps/web/schema/arcade-playability.sql을 읽기 전용으로 실행하여 지표를 확인할 수 있다.
  통계는 보관된 최근 7일 기록에 한정한다. unfinished에는 진행 중인 판도 포함되므로
  사용자가 실제로 포기하거나 이탈한 비율로 해석하면 안 된다.
