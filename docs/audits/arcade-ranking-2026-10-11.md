# 아케이드 랭킹 배포 전 검토 — 2026-10-11

대상은 `64f2753`의 랭킹 변경과 이 Mac mini에 보존된 기존 운영 수정이다.
내부 코드 검토·회귀 검사이며 외부 전문 감사 인증이 아니다.

## 확인한 경계

- 브라우저가 점수를 제출하는 공개 API는 없다. 기존 외출 서버가 결제 증거를
  확인하고 게임을 실행한 결과만 기록한다. 무료 연습은 순위에 들어가지 않는다.
- 입장 시 고정한 게임·시드·KST 날짜·차수가 결과와 일치해야 한다. 결과 원장,
  외출 진행 상태, 랭킹 행은 같은 SQLite 트랜잭션에서 저장한다. 결제 해시와
  입장 ID, 컬렉션/토큰/게임/날짜/차수의 유일성 제약이 중복 반영을 막는다.
- 토큰의 소유자가 바뀌어도 완료·미확정 입장 차수를 함께 계산한다. 해제된 차수는
  가장 낮은 빈 번호부터 재사용한다. 자정을 넘긴 복구도 원래 날짜와 시드를 유지한다.
- seller 조회에는 기존 bearer 인증이 필요하다. 웹 프록시는 고정 경로 GET만
  요청하며 사용자 쿠키·지갑 헤더를 전달하지 않는다. 리디렉션 거절, 10초 제한,
  응답 64 KiB 제한, 캐시 미스의 IP별 분당 120회 제한이 있다.
- 공개 응답은 허용 필드만 복사한다. 주소·결제 해시·권한·서명 키는 포함하지 않는다.
  순위표는 30초, 개별 전령 순위는 10초 캐시하며 오류는 저장하지 않는다.
- SQL의 외부 값은 바인딩하고, UI의 이름·문구는 React 텍스트로 렌더링한다.

## 재현 및 수정

`isRankingDay`가 `2026-99-99`, `2026-10-32` 같은 값을 검사할 때
`Invalid Date.toISOString()`에서 예외를 던졌다. 이로 인해 잘못된 seller 응답이
웹의 검증 함수를 통과하는 도중 정상적인 오류 응답 대신 처리되지 않은 예외를 만들었다.
임의 점수 등록이나 인증 우회는 확인되지 않았으며, 잘못된 입력에 대한 견고성 문제다.

날짜의 timestamp가 유한한지 먼저 검사하도록 수정했다. 공유 날짜·저장 레코드 검사와
웹의 board/standings 경로에 회귀 테스트 2개를 추가했다. 수정 전 두 테스트가 실패했고,
수정 후에는 잘못된 날짜가 거절되고 웹은 `503 ranking_unavailable`, `no-store`를 반환한다.
윤년의 유효한 날짜는 유지한다.

## 검증과 범위

`bun install --frozen-lockfile`, 전체 `bun run check`의 1,710 TypeScript 테스트와
61 Foundry 테스트, 타입·문서·저장소·로그·의존성 보안 검사를 통과했다.
차수·시드 변조 거절, 중복 결제 결과의 롤백, 소유권 이전 후 한도, 자정 경계,
주간 최고 5일·동점 정렬·출석, 인증·응답 크기·리디렉션·캐시·공개 필드 검사를 포함한다.

운영 DB의 암호화 백업을 별도 파일로 복원한 뒤 실제 `OutingStore` 초기화를 두 번
실행했다. 기존 13개 테이블의 행과 해시·schema version이 유지됐고 새
`arcade_guardian_ranked` 테이블과 4개 인덱스가 추가됐다. integrity/foreign key
검사도 통과했다. 예전 외출 기록은 새 랭킹에 소급 입력하지 않는다.

이번 변경은 기존 SQLite 파일에 테이블을 추가하며 D1 스키마·계약·키 교체가 필요하지 않다.
검토 범위에서 추가 배포 차단 문제를 발견하지 못했다. 이 결과는 새 랭킹으로 실제
GIWA 결제까지 성공했다는 뜻은 아니다. 운영 적용·브라우저 검증은
[배포 기록](../arcade-guardians-release.md)에 별도로 남긴다.
